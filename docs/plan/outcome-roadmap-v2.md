## 1. 现在继续、暂缓和调整什么

三条路线中，继续全面泛化会延后价值验证；整体推倒重写会丢失已验证机制并引入新风险。本版选择冻结现有职责、有限收口、最小调用方和效果门槛。选择成立的条件是现有核心能通过窄修复达到可用成本；若测量反驳这一点，先提交局部替代设计，不用沉没成本强行维持。

| 决策     | 内容                                                                                   | 理由与解除条件                                           |
| -------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 继续     | 阶段 7 当前实现的必要收口、已有正确性与兼容门禁                                        | 保留有效成果；不会因为已投入至少四小时而扩大目标         |
| 优先     | 7.5 测量与至多一个主要瓶颈的局部优化                                                   | 先解释成本；没有可辨认收益时可只交付测量                 |
| 缩小     | 阶段 8 最小进程入口、薄客户端和成果交接                                                | 一个真实调用方可用即可；包拆分、安装器和通用插件后置     |
| 继续     | 阶段 9 有界真实接入与取消/恢复验证                                                     | 只证明模型能够使用工具，不宣称协作更优                   |
| 必做门槛 | 阶段 10 效果评价                                                                       | 继续扩大产品前必须评价；“无优势”或“无法区分”也能完成评价 |
| 独立推进 | CoThink 的离线评价准备与小规模质量校准                                                 | 不等待 agent-sync 泛化全部完成；不与其重型门禁争用资源   |
| 条件推进 | 计划/范围建议、锁策略实验、证据反馈或讨论预算调整                                      | 只由测得的接入、等待、返工或质量缺口触发，一次一个问题   |
| 暂缓     | 更多 Agent、专用通信语言、全语言语义锁、分布式设施、数据库平台、Git 存储重写、自动发布 | 现阶段没有目标负载或收益证据支撑                         |

“必做门槛”表示没有评价结果就不扩大产品；不表示可以绕过用户启动指令、密钥配置或费用上限。

## 4. 防止再次陷入长时间施工

1. **先列缺口，再动文件。** 每次任务开头只列已通过、失效、未验与失败门禁，说明依据；已有源码/测试成绩不重复冒充本轮结果。
2. **一次一个变化理由。** 每个修复回合锁定一个反例和一组责任模块；同一缺口最多两轮有信息增益的修复。仍无进展时保留现场、报告下一条可证伪假设，停止扩大范围。
3. **长流程有判别目标。** 每次启动前写明它能回答什么、与上次输入差异在哪里、终止与清理方式。相同依据已通过的门禁可按实际依赖闭包复用；已失败的门禁不能靠历史成功覆盖。
4. **减少反馈循环成本。** 小修先定向回归，稳定后做受影响整合。重型磁盘/Git/Docker 测试彼此串行；准备文档与轻量分析可以并行，但运行时的源码和检查依据冻结。
   每个步骤由一名负责人维护依据与门禁账本；现有子任务在安全边界交接，不再围绕同一共享源码层层派发实现与重复审查。审查与子任务的数量服从实际独立职责，不能把增派人手当持续超时的默认解法。
5. **审查闭合，不无限加题。** 必须解决实际影响范围内的正确性和约定门禁；假想扩展记入暂缓列表。新发现真实缺陷必须报告，不能因两轮限制而忽略；需要超范围修复则保存未完成状态交接。
6. **时长不是完成证据。** 至少四小时的投入不推导出必须完成所有想法。也不设一个任意分钟数，强迫正在正确推进的真实验收被当失败；无新证据的重复尝试必须停止。

## 7. 后续扩展如何决策

阶段 10 与 C1 各交付一页决策记录：观察到的收益、代价、主要替代解释、最能改变判断的下一条证据。判断条件在实验前冻结：

- 静默覆盖、过期动作接纳或证据绑定失效：先修正确性，停止扩大模型实验。
- 最终质量不降低且时间/资源有可重复的可辨认收益：仅在对应任务类型继续；小样本不作普遍宣传。
- 质量改善但成本增加：明确每项新增收益及代价，由用户决定是否值得，不强行折成单一分数。
- 等待抵消返工收益：先做锁粒度/策略的小实验。
- 人工准备占主导：先做计划与范围建议，不先增加成员。
- 讨论没有可辨认贡献：保留显式讨论入口，暂停扩大讨论轮数和通信研究。
- 结果无法区分：报告不确定；下一次只补最关键证据，不自动增加场次或平台能力。
