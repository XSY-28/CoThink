# CoThink 可直接使用的施工提示词 v2

配套 [后续路线 v2](outcome-roadmap-v2.md)。此线评价“讨论是否改善结果”，不与 agent-sync 的事务可靠性混成一个指标。复制指定 text 块执行，单步结束即停止。本轮只保存计划。

## C0 离线评价准备与文档归位

可在 agent-sync 等待长验收时独立开展；保持其运行源码、镜像、检查依据和重型资源不受影响。

```text
请执行C0，仅做CoThink的离线评价装置和文档归位，零真实模型API，完成后停止。

目录：/Users/xubibi/Documents/CoThink/repo
读 docs/plan/outcome-roadmap-v2.md、docs/plan/discussion-progress.md、packages/argue/src/discussion/ 下的 engine.ts、decision.ts、json-codec.ts、policy.ts，以及 packages/argue-cli/src/discussion/commands.ts 与现有模型transport。按实际代码核对，不重写讨论引擎。
先检查agent-sync是否在跑冻结依据的长验收；本任务不修改它的核心/后端/配置/测试，不并跑重型Docker。若需要共享源码变化，保存具体接口缺口并停止，而不是同时重构。

交付一个窄的仓库外评价runner及冻结任务包，建议 work/cothink-quality-v2/，复用现有transport与CLI/DiscussionEngine。单模型基线只在实验runner实现，不为此新增产品模式、调度框架或第二套持久化。
任务固定3个，在看到实验输出前写清材料、可验证标准与可接受答案边界：
T1：从已有真实函数缺陷/回归记录选一个边界修复判断题；用独立测试或穷举小输入核对方案。没有实际缺陷来源时标作人工控制题，不冒充真实需求。
T2：两份有时间/版本身份的真实材料存在表面矛盾，要求分清现行事实、历史状态和未知；依据原始材料核对，不靠多数票。
T3：一个真实小型设计取舍题，给定约束、成本与失败情形，允许多个满足约束的答案；预先列出硬约束、关键反例和什么证据会改变选择，不把作者偏好当唯一真值。
问题与材料不可包含预备解答/工具历史修复代码，条件之间共享同一副本；宿主验收资料与模型可见输入分开。

C1拟比较单模型A、单模型B、A+B讨论；先冻结每条件输入/参数/预算/输出归一化、随机顺序、错误分类与usage口径。单模型固定三步：独立草稿、自查反例、修订定稿；每次最多8192分配输出，总池24576，最多6调用/180秒/单调用45秒，重试共享同一池。A+B走现有low、一轮上限、最多6调用、总池24576、180秒/单调用45秒。不裁掉必需review条目；离线若预留不够则记录能力缺口，不能付费试探或自动提额。
预算是资源帽不是精确等价费用；记录双方实际输入、输出、推理/缓存usage及未知项。两种单模型与讨论使用相同已确认模型profile、可见材料和等量可用总池，provider参数不自动换档。

离线用确定性transport回放验证：上限可满足合法完整协议、调用前持久占用、失败/unknown仍计费、崩溃不重置、取消、输出解析、原始与归一化结果对应。双模型用现有FinalResult，tied_preferences/incomplete保留原义；单模型最终文本归一到同一评价视图，不伪造共识或外部检查。
指标至少为：可验证错误/违反硬约束、可用最终结果、关键反例/新证据、纠正与退化、总时长/调用/usage、结构失败。共识率另列，不作质量主指标；开放题可用独立盲审，机器不能可靠判断的项保留未知。评价标准在揭示条件前冻结，不临时让另一个付费模型当裁判。

把README及必要使用说明区分为已发布基线、当前源码功能、实验中的施工工具，修复“已实现还写planned”等冲突；不把未发布源码宣传成已安装即可用，不借机重排全部文档或改安装行为。
输出 docs/cothink/EVALUATION_PLAN.md（新建）、work/cothink-quality-v2/PREFLIGHT.md 与冻结manifest/预算自测结果；说明3题来源、每个评价项证据方式、9场计划与隐私位置。所有现有格式、共识/选择语义和旧输入hash保留。只运行改动所需检查，不提交发布，不进入C1。
```

## C1 有界的讨论质量校准

这是独立的新付费预算提案，不从 agent-sync 阶段 9/10 账本挪用。用户明确启动 C1 并接受下列上限后才执行；本轮写文档不会启动实验。

```text
请执行C1，按已冻结装置比较单A、单B与A+B讨论。接受本步骤上限：3题×3条件=9场，每场最多6调用/24576分配输出，阶段最多54调用/221184分配输出；180秒/场、45秒/调用。实际成功可少用，失败/探测/重试/unknown均计入同一可恢复总账。仅执行本步骤，完成或额度耗尽即停止。

目录：/Users/xubibi/Documents/CoThink/repo
读 docs/plan/outcome-roadmap-v2.md、docs/cothink/EVALUATION_PLAN.md、work/cothink-quality-v2/PREFLIGHT.md 和冻结manifest。确认C0离线门禁与当前源码/输入依据一致。缺少合法配置、额度账本或完整预检时先完成零API工作并报告缺口，不进行收费探测。

沿已确认A/B的provider/model/endpoint/apiKeyEnv和私密路径；不换模型、不改推理档、不重新收集明文密钥。无已有直接人类授权或本步骤上限未被接受时只交付预检，本提示词不继承agent-sync实验或额度卡的额外次数。

9场的任务/条件顺序按C0预注册种子，逐场运行，同场讨论可自然并发。各条件使用独立会话、相同材料与总资源池，冻结工具/模型参数；不共享候选/答案/对话，不能根据第一题赢家改变后续顺序、预算或决策权重。单模型仍三步草拟/自审/修订，不偷用另一个模型或额外工具。
A+B复用现有入口/runner的low、max-rounds=1、max-calls=6、max-allocated-output-tokens=24576、max-duration-ms=180000、call-timeout-ms=45000；模型自己的复杂度估计不能放大这些上限。所有失败如实保留，不能删review条目来完成。

逐场保存公开可见的候选、证据引用、反例/异议和最终结果；用冻结标准评价：
- T1/T2中可验证结论由独立测试/材料判断，区分正确、错误、缺证据和未完成。
- T3按硬约束、适用边界、具体可执行性和关键反例盲评；允许多解，不以文风或与作者相同选择判优。
- 跟踪讨论是否纠正某成员错误、引入新错误、增加有用证据，或只是重复已有意见；不把声称“已验证”当工具证据。
- 记录输入/输出/推理/缓存usage及缺失，实际耗时、调用数和结构失败。没有可信价格就不报金额；相同输出帽不称严格同成本。
盲评缺少合格独立判断时输出匿名材料与待评项，结果保留未知，不能自行填写漂亮分数；现有本地分析不额外调用付费裁判。

基础设施错误暂停后续收费并保存状态；模型失败/超时/预算耗尽计为结果，不免费补场。中途必须修runner/源码则保存设计中断和已花费用，不混合新旧版本宣称同一实验完整完成。

输出 docs/cothink/EVALUATION.md、work/cothink-quality-v2/RESULT.md 和完整逐场/总账。结论限于这3题：相对单A、单B的收益与代价、哪些错误仍共享、是否值得保留当前讨论强度、下一条最有价值证据。单次每题不作显著性或普遍更强声明；不得用“共识更多”替代质量。
完成后停止，不调权重、不改默认策略、不新增Agent/语言/工具平台、不启动C2，不提交发布。
```

## C2 只修一个已证实的产品缺口

此提示词只在 C1 已指出具体问题、用户决定处理后使用。不能因为评价完成就自动建设“下一代 CoThink”。

```text
请执行C2，只处理C1证据中最影响可用结果的一项问题，默认零真实模型API，完成后停止。

目录：/Users/xubibi/Documents/CoThink/repo
读 docs/plan/outcome-roadmap-v2.md、docs/cothink/EVALUATION.md、C1的RESULT/逐场证据与当前discussion实现。若C1未完成、关键项未知或没有明确问题，交付下一条必要证据而不改功能。

先把问题归到以下一类，并只选择一项：
A. 缺少证据反馈：优先用现有versioned sources/continue和既有build结果转换，把已验证结果带入下一段；候选/来源/上下文身份要绑定，不把旧异步结果加入新段。这里只做窄适配，不开发通用检索/执行平台。
B. 讨论成本超过观察到的贡献：先给出现有轮数/额度选项的收紧方案和同场资源影响。未经充分证据不自动调decisionWeight或把偏好称可靠性，不为此新增调度引擎。
C. 分歧结果不便使用：先改善已有FinalResult的明确呈现，说明已确定部分、待选择项和缺失证据；保持tied_preferences/incomplete真实语义。不能偷偷选固定成员、改写他人答案或用无来源汇总掩盖分歧。
结构失败若是实际首要问题，限定到已有codec/反馈责任位置修复并按真实格式版本处理；不同时改A/B/C。

实施前写一页窄变更：具体输入反例、影响的现有模块与接口、预期可观察变化、保持的共识/作者所有权/预算/恢复保证、兼容办法与局部恢复方式。若需要新协议/状态版本、全新自动计划器或“共享作品系统”，本次只交付设计与成本后停止，不临时扩成新阶段7。

选择可在现有接口内完成的局部修复时，先保存反例和预期输出，再实施最少变化、定向回归和必要兼容检查；同一问题最多两轮有信息增益的修复。保留原冻结请求/旧输入hash和真实成功/失败证据，不通过减少必要评议覆盖换通过。

验收：原反例被处理，正常与边界输出可读且准确，旧语义/预算/恢复不退化，影响文件和回归有据；可以是文档/默认配置建议而非强行改源码。输出 work/cothink-quality-v2/C2-RESULT.md 及实际使用说明。
离线冻结输出重放只证明行为变化；任何“质量提高”或“更省成本”需要后续另行授权的真实复测，不能用旧9场成绩当修复后证据。无新增模型调用，不消费其他阶段剩余额度，不进入下一功能或发布。
```
