# Peer MVP validation ledger

This file separates deterministic tests from live-provider evidence. Passing local tests proves the protocol and local command behavior under controlled inputs; it does not prove a provider will obey the schema, complete within the output cap, or improve on a single model. Live acceptance records are maintained as local artifacts outside this public checkout.

The CLI test uses an actual loopback HTTP server and the real transport to cover start → provider failure → paused snapshot → one-member retry → completed segment → continuation → JSON export. It checks the 8192 output token cap in every request and confirms export makes no request. It is a controlled service, not a claim about live provider behavior.

Three scenario inputs are under `examples/peer/scenarios/`: omitted condition, continuing disagreement and insufficient evidence. DeepSeek/GLM completed all three initial runs with an 8192-token output cap. The omitted-condition run used `peer-v2` and recorded four committed rounds, six active claims, 14 evidence requests and one unresponded message; eight of nine attempts reported token usage. The other two runs used `peer-v4` with GLM `reasoning_effort: low`; each recorded four committed rounds and complete paired review. The value-tradeoff run still had one unresponded message. All 19 initial active claims were jointly accepted. A subsequent explicit continuation of the insufficient-evidence session completed segment 2 with a clearly labeled synthetic note, four additional calls under its six-call budget, and a new full review: six accepted, one uncertain and one disputed. Segment 1 reviews stayed intact. This demonstrates a live disagreement label after added context, not a persistent disagreement in the original three runs. Earlier live attempts paused on invalid output or truncation, which the program preserved rather than silently accepting.

Three single-member opening controls (six calls) returned valid openings whose input hashes matched the corresponding original member openings. They are useful observations, but cost was not matched and there was no repeated quality study. Mechanical source ID and line-range checks passed; qualitative counterexamples were noted, and neither model agreement nor source linkage proves factual correctness. A fair matched-cost outcome comparison and browser visual audit remain unverified. GPT/Claude remain unverified.
